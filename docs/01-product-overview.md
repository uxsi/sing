# 产品概述

## 1. 一句话

做一个**跨平台图形客户端**：内核用 **sing-box**，功能复杂度对齐 **Clash 常用能力**，配置格式与界面气质复刻 **SFM / sing-box 系**。

## 2. 目标用户与场景

- 日常需要 Rule 分流、节点切换、TUN、订阅/配置管理的用户。
- 同时存在**公司网准入（公司 VPN / 安全客户端）**与**个人出国代理**的桌面用户（首要痛点来自真实环境）。

## 3. 与现有产品的关系

| 对象 | 我们怎么对齐 | 我们刻意不做什么 |
|------|----------------|------------------|
| **sing-box 内核** | 直接复用官方 core；配置为 sing-box JSON（可含 `clash_api` 等实验字段） | 不 fork 改协议栈；不做「另一个内核」 |
| **Clash 生态** | 功能体感对齐：Rule/Global/Direct、策略组/选择器、订阅、TUN、混合端口、日志、延迟测试、面板控流 | 不追求 Clash Meta 全量规则世界；不做无必要的复杂语法 |
| **SFM（sing-box for Mac）** | 界面信息架构、配置编辑/导入、连接状态、模式切换的交互语言靠近 SFM | 第一期不保证像素级一一复刻；移动端后置 |
| **本项目 (sing)** | 自控产品边界；内置「办公模式 / 出国模式」与双 TUN/脏 DNS 防护 | 不做万能安全审计套件；不替代公司准入客户端 |

## 4. 成功标准（产品层）

1. 用户能用一份 sing-box 配置完成：导入 → 连接 → 切换节点/模式 → 看日志。
2. Clash 用户迁过来无明显能力缺口（见功能清单）。
3. 开着公司隧道时，启用**办公模式**后：内网可用，指定外网可代理，`git push`（GitHub SSH）稳定可复现成功。
4. **出国模式**下尽量独占 TUN、DNS 干净，行为接近「只开 SFM、不开公司隧道」。

## 5. 非目标（明确不做）

- 重写代理协议实现。
- 完整复刻 sing-box 全部实验特性与冷门 inbound/outbound。
- 与公司安全客户端对抗、绕过公司安全策略（只做共存与可预期分流，并提示风险）。
- 第一期覆盖 iOS/Android 上架级体验。
